# Signal Validation Lab · 通用策略信号验真

**当任意策略发出一个信号，3个交易日之后，价格上涨了多少次？这种现象能否在后续未参与选型的时段中保留？**

这是一个接收外部策略信号的研究工具。策略可以是规则、模型或人工记录；本项目不生成信号，不内置任何特定资产或交易策略。核心指标是**信号日收盘到第3个市场交易日收盘的上涨比例**，不是账户收益、净交易胜率，也不是“3天内曾经涨过”的比例。

项目作者提出研究流程，代码使用 AI 辅助实现；计算规则、测试和适用边界均可检查。默认演示完全使用合成数据，不发布个人行情缓存、账户信息、密钥或历史私有策略。

## 一分钟运行

需要 Python 3.10+。在项目目录执行：

```bash
python -m pip install -e .
python -m signal_validation demo --output outputs/demo
```

打开 `outputs/demo/report.md` 查看报告，`result.json` 保留每折和逐信号明细，`protocol.json` 保存验证配置和哈希。也可先查看[合成演示报告](examples/demo-report.md)。演示的0/1信号由固定随机种子生成，只用于检查流程，不能作为真实策略效果证据。演示日历是合成工作日，不代表真实市场节假日。

## 输入任意策略的信号

UTF-8 CSV，一行一个标的的一个市场交易日：

```csv
date,symbol,close,signal_A,signal_B,eligible
2024-01-02,ASSET_A,100,1,0,1
2024-01-03,ASSET_A,99,0,0,1
2024-01-04,ASSET_A,101,0,1,1
2024-01-05,ASSET_A,102,1,0,1
```

这段短表仅说明格式，不足以运行18个月训练的滚动验证。

| 列 | 含义 |
|---|---|
| `date` | ISO日期的市场交易日，建议统一写成 `YYYY-MM-DD` |
| `symbol` | 标的唯一标识；同一标的的价格口径必须一致 |
| `close` | 正数收盘价；空值表示缺失，不填造价格 |
| `signal` 或 `signal_名字` | 单候选用 `signal`；多个候选用 `signal_A` 等。1=触发，0=明确未触发，空=未知 |
| `eligible` | 可选，1=允许纳入研究，0=排除；不提供时全部允许。由使用者在信号日可知信息下生成 |

不同参数版本可以分别作为候选信号列，例如 `signal_variant_a`、`signal_variant_b`。本项目只验证已经生成的信号，不在历史行情中替你重新实现这些策略。

建议另提供完整交易日历 `calendar.csv`：

```csv
date
2024-01-02
2024-01-03
2024-01-04
2024-01-05
```

如果不传 `--calendar`，采用输入CSV的日期并集，无法识别整个市场都漏掉的日期。混合市场应按各自完整日历分开研究。调整价格必须来自一致、适用于该信号定义的数据口径；工具不会替使用者核验复权、幸存者偏差或信号生成时使用的信息。

## Phase 1：实验室探索

```bash
python -m signal_validation phase1 --input data/signals.csv --calendar data/calendar.csv --start 2019-01-01 --end 2020-07-01 --output outputs/discovery
```

所有日期区间**开始含、结束不含**。以上日期只是命令示例，需替换成自己的数据范围。

- 对每个候选统计三日上涨比例、有效样本、缺失端点、尾部未成熟样本以及未触发日期基准。
- 默认同一标的信号在 `t` 被接受后，跳过 `t+1`、`t+2`，最早 `t+3` 再接受。用 `--cooldown-sessions 1` 可保留每天再次触发的信号。两种口径不能混报。
- 样本内按有效样本数至少10及上涨比例选优，同率按候选名字稳定排序；10只是软件筛选下限，不代表统计充分。
- 在8个连续日期块中生成各候选的成功数/有效数，真实枚举CSCV并计算PBO。标签必须在本块成熟；数据不足则明确“未计算”。PBO比较族包含全部输入候选，不悄悄删掉无样本候选；某次切分出现零分母时跳过该次切分并披露数量。CSCV仅要求各半区计数为正，未套用Phase 1/WFA的10样本门槛，因此它诊断的是候选族的基础选优过程，不是整个门槛流程的精确风险估计。
- 日期块重采样同时保留同日各标的观测，输出上涨比例相对基准差值的描述性区间。

如果已根据 Phase 1 诊断确定候选围栏，可以在再次生成探索协议时显式指定，例如 `--validation-candidates A,B`。默认保留全部候选。软件不把最高样本内胜率、冷却或某个固定PBO阈值当成“策略有效”的证明。

## Phase 2：固定规则后滚动验证

```bash
python -m signal_validation walk-forward --input data/signals.csv --calendar data/calendar.csv --protocol outputs/discovery/protocol.json --output outputs/validation
```

默认使用18个日历月训练、3个日历月OOS、3个月步长，并在训练结束后隔离5个**市场交易日**。候选围栏、冷却、最小样本数和窗口设置来自探索阶段的协议；验证命令不接受临时改围栏再混称同一实验。

每一折只用训练截止前已经成熟的三日标签选候选；保持该候选不变，在下一折OOS统计。OOS末尾未成熟的信号单列，不跨到本折结束之后取价格。OOS区间不得重叠，训练不足的折保留跳过原因。总体比例采用总上涨数除以总有效观察数，不把各折百分比简单平均。

首次OOS不会早于探索结束。协议里的默认训练起点是探索结束前18个月；输入需要覆盖这个训练窗口。新数据可以追加到输入CSV，报告保存每次输入哈希。更换已经提供的交易日历需要新建实验。

如果环境过滤是策略的一部分，使用者必须先用当时可知信息生成 `eligible` 或新的候选信号，再冻结配置。工具不根据OOS结果自动寻找环境过滤器；看过结果再改条件，就是新的研发实验，需要新的未见数据。

## 怎样阅读结论

1. `win_rate`：固定第3个交易日收盘严格高于信号日收盘的比例；持平不算上涨。
2. `baseline_rate`：同样 `eligible=1` 条件中该候选原始信号明确为0的可评估日期上涨比例。它不是因果对照组，没有自动作市场状态、风险或信号强度匹配。
3. `lift`：上述两个比例之差；高胜率也可能只是市场本来就容易上涨。
4. `bootstrap`：按日期块重采样的差值区间。结果依赖数据、区块长度和样本量，不证明所有时间相关性都已解决。
5. `pbo`：指定候选族和CSCV切分下的回顾性选优风险，不是策略失效概率或未来亏损概率。

不会从手续费直接推导51%的盈亏平衡胜率，也不会把“Z>1.96”“PBO<20%”写成通用验收保证。冷却不能保证样本独立，3日上涨比例也不能代替平均盈亏、成本和可成交性。软件不自动作出“可实盘”裁决。

配置哈希用于复现和发现误改，不是可信时间戳。引擎能限制自己的标签读取边界，但不能证明外部信号没有前视，也不能证明使用者从未看过历史OOS数据。

## 开发与复现

```bash
python -m unittest discover -s tests -v
python -m signal_validation --help
```

运行时只依赖NumPy，不需要API密钥、行情账户或联网下载。输出目录必须是新的或空目录，避免覆盖实验。单标的单候选可运行；只有一个候选时PBO没有选优风险可比对象，会明确不足。

主要文件：

- `signal_validation/research.py`：数据校验、固定三日标签、冷却、日期块区间和WFA。
- `signal_validation/pbo.py`：通用CSCV选优风险诊断。
- `signal_validation/cli.py`：合成演示、配置冻结、命令行和报告。
- `tests/`：缺失、日期边界、冷却、协议完整性及统计行为测试。

方法参考：[Bailey等，The Probability of Backtest Overfitting](https://scholarworks.wmich.edu/math_pubs/42/)；PBO模块按本项目的三日比例目标实现CSCV框架，没有复制第三方项目源码。项目采用[MIT许可](LICENSE)，依赖各自保留原许可。
